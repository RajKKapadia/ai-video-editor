# Cutline guide

See the [quick start](../README.md#quick-start) to launch the editor. Run `bun run build` to check TypeScript and build the front end.

## Timeline editing

Create a project from the home screen, then import a supported video or audio file. Select a clip in Project media and scrub to the desired start and end. Press **I** and **O** to mark them, then **V** to insert that range at the timeline playhead. Use **P** to clear marks and **A** or **S** to jump between cuts in the sequence viewer or marks in the source viewer. **Space** plays or pauses the active viewer.

When a video with embedded audio is on the timeline, its linked audio appears on **A1**. Both parts share the same edit, so selecting or removing either part applies to both. Use **Fit** or move the zoom slider all the way left to see the whole sequence. Zoom in around the playhead for a closer view.

To edit a timeline range, scrub to its start and use **In**, then scrub to its end and use **Out** in the timeline range bar. **I**, **O**, and **P** mark or clear the active viewer: Source marks choose the media to insert; Sequence marks choose the timeline to edit. The highlighted timeline range spans both linked tracks. A single In mark selects through the sequence end, and a single Out mark selects from the start.

**Delete** (or **Backspace**) removes the marked timeline range and closes the gap. **Replace** (**B**) swaps it for the selected source clip's In/Out range; later clips shift if the source range has a different duration. Without timeline marks, Delete and Replace act on the selected timeline clip. Timeline marks take priority over clip selection, and an invalid range must be corrected or cleared before editing. Choose the replacement clip in Project media and mark its source range before pressing Replace. **Ctrl/⌘ Z** restores the prior timeline. Timeline marks clear after an edit or Undo; source marks remain available. Cuts must leave at least one frame in any retained fragment.

Run `bun test` for range-edit checks. With a disposable Chrome profile and Vite running as described in [docs/performance.md](performance.md), run `bun run check:timeline` for range marking, Delete/Replace, linked audio, Undo, and narrow-window checks.

**A1** draws waveforms for linked and standalone audio. Zoom in to see quiet gaps and click the waveform to put the playhead there. Waveforms are analyzed once per source and saved locally. The desktop app uses FFmpeg from your system PATH for large clips. The browser preview can analyze clips up to 32 MiB and eight minutes in supported formats.

## Assistant and timeline cleanup

Select **Clean up timeline → Draft adaptive cleanup**, or open **Assistant → Draft cleanup**. Configure an AI provider in Settings first. An optional brief can explain the desired pacing and meaningful demonstration waits. The default brief asks for a flowing sequence assembled from available fragments, preserving unique information and necessary connecting words. A thought can span several attempts: for “build an AI” followed by “AI agent from scratch,” the planner can compare keeping either occurrence of “AI” and removing the overlap and intervening pause.

Cutline measures voice boundaries locally and transcribes using the engine selected in Settings → Transcription. The planning provider receives the brief, transcript, timing, and measured connection alternatives. With local Whisper, Cutline also retranscribes the assembled speech to check the retained words and can send verification feedback for one replanning pass. OpenAI transcription uploads audio to OpenAI and uses timing evidence for the draft. Video and source paths stay on the device. See [Adaptive cutting](adaptive-cutting.md) for implementation and limitations.

Review the proposed removals and play the original footage to check what happens on screen. The agent uses transcript context to preserve intentional waits and demonstrations; describe their purpose in the brief when it is not apparent from speech. Check the cuts you want, or use **Select all pauses** and **Select all retakes**, preview the joins, then select **Apply selected**. The two select-all buttons add to your selection; **Clear selection** unchecks everything. Nothing is selected automatically. Applying part of a draft keeps the remaining suggestions with updated timestamps. One Undo restores the prior timeline, draft, and selection while the editor is open. Timeline In/Out marks are for manual edits; assistant analysis covers the entire current sequence. Other timeline edits made during drafting or review require a fresh draft.

Cleanup first reviews the complete transcript together when the estimated request fits the planning context budget. **Settings → AI providers → Planning context budget** defaults to 32,768 tokens; use a value within the selected model’s documented context window. This budget is not detected automatically. The estimate includes instructions, timing evidence and response schema, with room reserved for the output and safety headroom. Word details are inspected only when needed. If the request exceeds the budget, or the provider rejects its size or cannot complete its cut list, Cutline uses smaller overlapping sections and compares likely repetitions between distant sections. Local analysis supports up to 4 MiB of transcript text. Planning has a separate 4 MiB serialized-input guard; transcript questions retain their 96 KiB guard.

The planner proposes, validates and audits its draft against the same original transcript. It stops when the cut plan stabilizes, after at most three valid draft passes, or after eight total inspection/correction requests. Each planning scope has a five-minute deadline. A later failed revision preserves the preceding validated draft with a review note. This loop does not apply cuts or repeat transcription. Existing measured speech padding remains in place; plans leaving less than 0.15 seconds of retained audio between separate removals are rejected for review, while adjacent removals can form one join.

Expand **Planning details** in the result to inspect transcript coverage, completed or failed scopes, pass counts and validation outcomes. The draft and these diagnostics save with the project. Separate audits in `workspace/cleanup-reviews/` record every cleanup run’s planning passes and original source-range mapping, including failed reviews; `cleanup-review-<project-hash>.json` holds the latest result. Transcript questions do not overwrite these audits. Diagnostics retain the analyzed timeline identity when partial Apply shifts the remaining suggestions. If a proposal cannot be repaired or placed safely, its review note explains what was left unchanged; independent valid suggestions remain available. Restore unavailable sources and analyze again to finish an incomplete review.

Under **Advanced**, use **Analyze transcript and pauses** to review measured gaps separately. **Apply pauses and find cuts** shortens the checked gaps and looks for cuts on the edited timeline. You can also find cuts with the original pauses. Each apply step supports Undo. **Ask about transcript** answers questions about the current sequence. Advanced analysis and transcript questions send recent conversation to the provider along with the transcript.

Use **Clean up timeline → Basic analysis** to shorten quiet pauses, compare repeated takes, or do both. Quiet-gap candidates include recording lead-in and tail silence and require at least 0.5 seconds of measured quiet, retaining about 0.15 seconds next to speech. Use adaptive cleanup for contextual decisions about intentional pauses. The first run downloads the Silero v5.1.2 voice detector (under 1 MB). Retake analysis uses the selected transcription engine. Local mode downloads the selected multilingual Whisper model. OpenAI mode uses the saved OpenAI API key. FFmpeg must be on PATH. The desktop build uses CMake and libclang to compile the local speech engine.

Temporary provider failures receive at most two retries, with cancellable backoff and supported `Retry-After` delays. Authentication and billing/quota failures are reported without automatic retries. If contextual planning remains unavailable, measured quiet gaps can still be reviewed manually, with a notice that repeated material and intentional pauses were not checked. An entirely quiet sequence can be cleared after preview; Undo restores it.

### Transcription settings

Open **Settings → Transcription → Transcription engine** and select **OpenAI API · word timestamps**, then **Save and use**. Save your OpenAI key under **AI providers** first. Transcription uses that key independently of the active planning provider. It sends mono 16 kHz WAV audio to OpenAI's fixed transcription endpoint, in uploads under 20 MB split between measured speech groups. A speech group longer than ten minutes without a safe boundary is left for review. Uploads, retries and response reads are cancellable; authentication and quota failures are reported. API mode does not download or run a local Whisper transcription model, and does not silently switch engines on failure. Local Silero voice detection still checks cut boundaries.

The timestamp adapter uses `whisper-1` with `verbose_json` and word timestamps. [OpenAI documents this model's shutdown for February 26, 2027](https://developers.openai.com/api/docs/guides/transcription); the newer file transcription workflow does not document equivalent word timestamp output. Replace this adapter before shutdown. Zero-duration words remain in the transcript but cannot define an internal word cut boundary; malformed, overlapping or incomplete timing leaves the affected source for review. Provider timings still require auditioning joins.

Choose **Local Whisper** to use **Auto · balanced**, **Auto · prioritize accuracy**, or a fixed **Small**, **Medium**, **Large v3 Turbo**, or **Large v3** model. Processing device is separate: **Auto** uses an available accelerated worker; **CPU** disables acceleration. A fixed model never changes when GPU processing falls back to CPU. Model downloads range from 488 MB for Small to 3.10 GB for full Large v3; models are downloaded separately from the installer, pinned to known revisions, and SHA-256 verified before use.

Auto reserves at least 2 GiB or 25% of system RAM for editing, whichever is larger, and accounts for currently available memory. Shared GPU memory is not added to RAM. It shortlists a model, then measures an embedded eight-second English speech sample on the selected backend after warm-up, using the same decoding settings as cleanup. Balanced mode can try one smaller model if the measured transcription time exceeds 1.5 times the sample duration. Accuracy mode favors its largest fitting candidate. Either Auto mode can try one smaller candidate if the model cannot complete its test. The measurement is a speed and backend-health check, not an accuracy evaluation or a guarantee for every language or long recording. **Download and test** runs a fresh check; **Refresh hardware** clears old measurements. Explicit model selections fail with an actionable error if available memory is insufficient.

Preferences and benchmark results persist in `speech-settings.json` in the platform app-config directory. Benchmark profiles include CPU, memory capacity, usable GPU/backend identity, OS/architecture, and speech-engine version; available memory and backend availability are inspected again before analysis. A preparation job is cancellable and shares the cleanup job limit. A cleanup run keeps one isolated transcription worker and reuses its loaded Whisper model across timeline ranges. The CPU decodes and detects speech for the next range while the worker transcribes the current range. A failed GPU benchmark or transcription retries on CPU with the same model and reports the fallback. The editor stays CPU-capable when an optional acceleration worker cannot start.

### Optional speech acceleration builds

Default Linux/Windows builds include CPU speech support. macOS builds enable Metal. To produce a CPU-capable editor with an optional CUDA or Vulkan worker, use `python3 scripts/build-speech.py --backend cuda` (or `vulkan`). Use `--backend cpu` for a portable build without an optional GPU worker. Add `--no-bundle` to build without installers. This requires the corresponding development toolkit, plus compatible runtime libraries/drivers on accelerated users' machines. The helper builds the accelerated executable separately and bundles it under `speech-worker/`; the main executable is built without the optional GPU features. It disables build-machine-specific CPU instructions for redistribution. Outputs are under `src-tauri/target/speech-portable/release/` (`speech-portable-cpu/release/` for CPU builds), with installers in `bundle/`. Keep the worker and editor from the same release. For development, the CPU app also discovers `src-tauri/speech-worker/`. Direct Cargo features `speech-cuda` and `speech-vulkan` are useful for diagnostics, but such binaries depend on that backend's runtime and should not replace the portable CPU editor. Cross-platform installers and GPU drivers must be tested on their target systems.

### AI providers

For repeated takes, open **Settings → AI providers** and choose OpenAI, Anthropic, Google Gemini, or an OpenAI-compatible endpoint. Enter the model ID and API key, save the provider, and optionally test it with synthetic text. Compatible servers use the API base URL, for example `http://127.0.0.1:11434/v1` for a local server. Cutline stores keys in the system credential store. The selected provider receives transcript text and utterance IDs in one request, up to 48 KiB of serialized transcript. Audio is uploaded only when OpenAI transcription is selected. Shortening pauses works offline after the voice detector is installed.

Play either take to compare delivery. Check the cuts you want, preview the joins, and select **Apply selected**. Undo restores the prior timeline while the editor is open. Word timing supports cuts within continuous speech. Missing or ambiguous alignment leaves that proposed cut unchanged with a review note.

## Export

In the desktop editor, open **Export** in the top bar. Choose a resolution, frame rate, and quality, then select **Export MP4** and a destination in the save dialog. Output uses H.264 video and 48 kHz stereo AAC audio. The default is 1080p at 24 fps with balanced quality. Source resolution is also available when the first video has a supported size. Install FFmpeg with `libx264`, the AAC encoder, and `ffprobe` on PATH.

Export renders the timeline as it was when you started the job, including applied cleanup edits. Source in/out points and clip order are preserved, with cut boundaries rounded to output frames. Picture is scaled to fit with letterboxing. Video without audio gets silence, and audio-only segments get black picture. Linked files are read directly. Older cached imports and sample media are staged in 1 MiB chunks.

The Export section shows progress, the active encoder, cancellation, the completed file path, and **Show in folder**. Cutline automatically uses NVIDIA NVENC when FFmpeg and the GPU can encode at the requested output size. A cancellable two-frame test checks the actual encoder with a ten-second initialization timeout. If hardware encoding is unavailable, Cutline uses CPU encoding with the `veryfast` preset and up to eight encoder threads, scaled to available CPU cores. Decoding uses up to four threads and filtering up to two. Quality uses targets 18/22/26 for High/Balanced/Smaller with either encoder; CPU CRF and NVIDIA CQ do not guarantee identical visual quality or file sizes.

One export runs at a time, rendering cuts sequentially. If the GPU fails while rendering a cut, Cutline discards that attempt and restarts all cuts on CPU, keeping encoder settings consistent throughout the MP4. Intermediate video and PCM audio files use the destination drive. Temporary media is removed on success, cancellation, or error. A previous file at the selected destination is replaced only after the new MP4 is complete. The renderer rejects source-media destinations. Export is available in the desktop app.

Run `cargo test --manifest-path src-tauri/Cargo.toml --lib export::tests -- --include-ignored --test-threads=1` to include real FFmpeg checks of mixed video/audio output, source trims, frame counts, cancellation, unavailable hardware, and full CPU retry after a GPU failure. The 4K/60 NVIDIA check runs when a working NVENC device is available. Unix fallback tests also require Python 3. With the disposable browser session described in the performance guide, run `node scripts/check-export.mjs` to check the Export UI and native bridge using mocked desktop responses.

For a short comparison against the previous CPU pipeline, set `CUTLINE_EXPORT_BENCHMARK_SOURCE` to a video at least 12 seconds long and run `cargo test --manifest-path src-tauri/Cargo.toml --lib export::tests::benchmark_real_source_4k60_export -- --ignored --nocapture`. This exports the same three two-second ranges at 4K/60 with both encoders, checks output frames, and prints elapsed time. It requires working NVIDIA hardware and uses temporary output files.

## Project storage

Desktop imports link to the original media by absolute path. If a file is moved, deleted, or inaccessible, Cutline shows **Asset unavailable** in the editor and keeps its cuts on the timeline. Restoring the file at its saved path brings the clip back online.

Desktop project details, timeline edits, and thumbnails are stored in `workspace/projects.json` under the app cache. Deleting the `workspace` folder clears the project list. The source files live at their original paths.

Cutline saves transcripts in `workspace/transcripts/project-<project-id>.json`. Each utterance includes text, a clip ID, and timestamps in seconds for the analyzed timeline and the original clip. The transcript records the selected model file, engine version, and processing devices. Cleanup and transcript questions share a local speech analysis cache for each project, including word alignment. Reordering a clip or splitting it at a measured quiet gap can reuse the original transcription. Derived cut boundaries are refreshed on every cache hit. Cutline analyzes new or changed media and ranges trimmed through speech, and transcribes again when the selected transcription engine, model, or alignment format changes. The first run after an alignment upgrade also recalibrates the selected speech backend.

Structured transcripts are also saved in `workspace/transcripts-<project-id>.sqlite3` for both engines. Tables record media revision identities, analysis provider/model and range, utterances, individual words, and analyzed timeline runs. Word times are absolute offsets in the original media; stable word IDs survive cached trims and timeline reordering. Changed media, model, alignment version or word content produces distinct identities. Transactions keep each source write consistent. Older JSON caches populate these tables when reused; no bulk reanalysis is required. Timeline rows represent analysis snapshots, not the current saved edit. Future search must map results through the current timeline and check its revision before proposing edits. Embeddings and vector search are not implemented in this stage.

The assistant saves completed conversation turns from Advanced and transcript questions by project in `workspace/assistant.sqlite3` and restores them when you reopen the project. Completed cleanup drafts, selected checkboxes, and the pending Advanced cut-review step save automatically with the project in `workspace/projects.json`. Reopening the project after an app restart restores the matching draft and selection; previews and in-progress analysis do not resume. A failed or cancelled replacement analysis keeps the previous completed draft. Deleting the workspace clears the project list, drafts, transcripts, and conversations.

| OS | Desktop workspace cache | Speech models |
| --- | --- | --- |
| Linux | `~/.cache/com.logan.tauri-app/workspace/` | `~/.local/share/com.logan.tauri-app/speech-models/` |
| macOS | `~/Library/Caches/com.logan.tauri-app/workspace/` | `~/Library/Application Support/com.logan.tauri-app/speech-models/` |
| Windows | `%LOCALAPPDATA%\com.logan.tauri-app\workspace\` | `%LOCALAPPDATA%\com.logan.tauri-app\speech-models\` |

On Linux, `XDG_CACHE_HOME` and `XDG_DATA_HOME` override the corresponding default base folders.

Existing desktop projects migrate to the cache on first launch and retain access to media previously copied into IndexedDB. The regular browser preview saves project state in browser storage and copies imported files into IndexedDB.

## Development checks

Performance checks and resource scheduling limits are documented in [docs/performance.md](performance.md). Run `bun test` for the bounded import scheduler checks. Browser regression and stress-test instructions are included in that document.

Run `cargo test --manifest-path src-tauri/Cargo.toml --lib` for cleanup and provider checks. With a disposable Chrome session and the Vite dev server running as described in the performance guide, run `node scripts/check-cleanup.mjs` to check preview, apply, undo, and project persistence using mocked native responses.

For transcription checks, run `node scripts/check-speech.mjs` against a disposable browser as above. `python3 scripts/check-speech-worker.py --worker /absolute/path/to/worker --model /absolute/path/to/ggml-large-v3.bin --device 0` verifies a real accelerated model; omit `--device` for CPU. Set `CUTLINE_SPEECH_WORKER` to the built CPU editor executable and `CUTLINE_SPEECH_MODEL` to a downloaded model, then run `cargo test --manifest-path src-tauri/Cargo.toml --lib cleanup::worker::tests -- --include-ignored --test-threads=1` to include real same-model CPU recovery and child-process cancellation checks.
